# Безопасность

## Как сообщить об уязвимости
Не создавайте открытую задачу. Напишите через **Security → Report a vulnerability** в этом репозитории (закрытое сообщение). Ответ — в течение 7 дней.

Укажите: где уязвимость, как повторить, чем она грозит. Не прикладывайте настоящие персональные данные.

## Что уже сделано
- Пароли — bcrypt; 5 неудачных входов подряд — блокировка на 15 минут.
- Сессия браузера — httpOnly-cookie `SameSite=Strict` + заголовок `X-Immunity-CSRF` для изменяющих запросов.
- Смена пароля, смена роли и «выйти везде» отзывают все токены.
- Строгая проверка входных данных (неизвестные поля и строки вместо чисел отклоняются), лимит тела запроса 3 МБ.
- Тексты проверок угроз не сохраняются — только уровень и коды признаков.
- Сводки организаций — только агрегаты, только по согласившимся, не меньше 5 человек.
- CSP, `X-Content-Type-Options`, `Referrer-Policy` в nginx.
- Секретов в коде нет: только переменные окружения.

## Известные ограничения
- Нет общего ограничения частоты запросов (кроме блокировки входа): регистрацию можно нагрузить скриптом. Запланировано — `ROADMAP.md`, этап D.
- Нет подтверждения email.
- Для нагрузочных проверок используйте только свой локальный сервер.
