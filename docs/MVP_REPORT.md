# Отчёт: MVP Architecture & Foundation

ТЗ «PROJECT: IMMUNITY — MVP ARCHITECTURE & FOUNDATION». Дата: 08–09.11.2026.

Порядок этапов: 1 → 3 → 2 → 4 → 5. Backend сделан раньше frontend, чтобы интерфейс сразу строился на настоящем контракте API (типы генерируются из OpenAPI), а не на заглушках. Каждый этап проверен тестами до перехода к следующему.

## Этап 1. Анализ и проектирование — готово
`docs/ARCHITECTURE.md`: 14 модулей прототипа, карта зависимостей, что куда переносится, технический долг, структура frontend и backend, схема БД, контракты API, план миграции. В разделе 9 — отклонения, принятые при реализации.

## Этап 3. Backend — готово
- FastAPI, Pydantic (строгие схемы, неизвестные поля запрещены), SQLAlchemy 2, Alembic (миграция `0001`), PostgreSQL 16; настройки только из переменных окружения, секретов по умолчанию нет.
- Модели: организации, пользователи, аудитории, навыки, маркеры, сценарии и озвученные реплики, попытки тренировок, проверки угроз (без исходного текста), журнал аудита.
- Роли: learner, teacher, org_admin, admin. Роль нельзя задать при регистрации; смена роли отзывает токены.
- `/api/v1`, OpenAPI — `/api/v1/openapi.json`, документация — `/api/v1/docs`, копия контракта — `docs/openapi.json`.
- Контент (84 сценария, 111 реплик с аудио, навыки, маркеры, памятки) и правила детектива загружаются из прототипа, ничего не переписано вручную.

**Запуск:** uvicorn на PostgreSQL 16, проверка curl: регистрация → вход → профиль → сохранение попытки → история → проверка ссылки; CORS и `/health` — ок.

## Этап 2. Frontend — готово (фундамент)
- React 19, TypeScript (strict), Vite 6, Tailwind 4, React Router 7, TanStack Query 5, Zustand 5.
- Адаптивный макет: боковая панель на десктопе, верхняя строка и нижняя навигация на телефоне; ссылка «к содержанию», видимый фокус, светлая и тёмная темы, крупный текст, уважение к `prefers-reduced-motion`.
- Дизайн-система на токенах прототипа: кнопки, поля, панели, уведомления, теги, скелетоны загрузки, пустые состояния, состояния ошибки с «Повторить», всплывающие уведомления, логотип.
- Страницы: Главная (индекс с погрешностью, карта навыков, рекомендация, последние тренировки), Обучение (каталог, «Верю — не верю»), Защита (проверка сообщения, ссылки, письма; памятки с источниками), Аналитика (навыки, история с фильтром и страницами, сводка организации для teacher/org_admin), Профиль.

## Этап 4. Интеграция — готово
| Требование | Как работает |
|---|---|
| Регистрация | `POST /auth/register` → автоматический вход |
| Авторизация | `POST /auth/session`: токен в httpOnly-cookie, `SameSite=Strict`; изменяющие запросы — с заголовком `X-Immunity-CSRF` |
| Профиль | `GET/PATCH /users/me`, смена пароля, выход везде, удаление аккаунта |
| Список сценариев | `GET /scenarios` (без ответов), `GET /scenarios/{kind}/{slug}` |
| Сохранение результатов | Тренажёр «Верю — не верю» сохраняет каждую карточку `POST /attempts`; навык и сложность сервер берёт из базы |
| История | `GET /attempts` с фильтром и страницами; оценка навыков `GET /skills/me` |
| Данные в PostgreSQL | Все пользовательские данные — в БД. В `localStorage` только тема и размер текста |
| Перенос старого прогресса | Файл экспорта прототипа → `POST /users/me/import` с той же проверкой, что в прототипе |

## Известные ограничения
- **Docker не проверен**: в среде разработки нет Docker daemon. `docker compose config` проходит, но образы не собирались. Всё остальное проверено на локальных PostgreSQL 16, uvicorn и `vite preview`.
- **CI не запускался**: workflow написан, первый прогон будет после публикации репозитория на GitHub.
- Safari и Edge не проверены (нет движков в среде); в CI — WebKit и Edge для прототипа, Chromium для нового интерфейса.
- В новом интерфейсе перенесён один тренажёр — «Верю — не верю». Звонки, переписки, сайты и диагностика открываются в прототипе, это подписано в интерфейсе. Перенос — этап A в `ROADMAP.md`.
- ИИ на сервере не подключён (нет AI Gateway): `/health` отвечает `"ai": false`, интерфейс пишет «Разбор с ИИ появится после подключения защищённого ИИ-шлюза».
- Нет подтверждения email и восстановления пароля (нужен почтовый сервис). Ограничение частоты — только блокировка входа.
- Кабинет организации: API есть (создание, участники, сводка), в интерфейсе — только просмотр сводки. Создание организаций и назначение ролей — через API.
- Голоса Silero — только некоммерческое использование (`docs/THIRD_PARTY.md`).
