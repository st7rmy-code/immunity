# Дорожная карта

Состояние на 08.11.2026. Подробности сделанного — `docs/MVP_REPORT.md` и `docs/STABILIZATION.md`.

## Сделано
- **Стабилизация прототипа** (ТЗ «Техническая стабилизация»): безопасный импорт, единое согласие для ИИ, честный демо-скоринг, уровни признаков детектива, разбор URL, маскирование PII, защита от устаревших таймеров, тесты 12 модулей.
- **Фундамент MVP** (ТЗ «MVP Architecture & Foundation»): FastAPI + PostgreSQL + Alembic, роли и права, React-интерфейс в стиле прототипа, интеграция (регистрация, вход, профиль, сценарии, сохранение тренировок, история), тесты, Docker Compose, CI.

## Этап A. Перенос тренажёров в новую версию (следующий)
Цель — прототип больше не нужен пользователю.
1. Движок сценарного собеседника (звонки и переписки) → `frontend/src/features/simulator/` на TypeScript; контент — из `GET /scenarios/{kind}/{slug}`; озвучка — `lines[].audio_url`.
2. Тренажёр сайтов и диагностика A/B (`item`) с сохранением в `/attempts` (фаза `pre`/`post`).
3. Интервальные повторения и рекомендации (`Rec`) — на backend (`app/domain/recommend.py`), фронтенд показывает ответ.
4. После переноса: прототип убирается из навигации, `/prototype/` остаётся только для импорта старого прогресса.

## Этап B. AI Gateway
До него ИИ на сервере выключен (`/health` → `"ai": false`).
1. `backend/app/ai/`: провайдер-независимый адаптер, маскирование PII на сервере (перенос `PII` из прототипа + тесты), лимиты на пользователя, журнал запросов без текста, таймауты.
2. Согласие: в запросе — явный флаг и хеш показанного пользователю содержимого; сервер отправляет ровно его.
3. Ответы — только через нормализацию схемы (как `normSchema`), при конфликте с правилами — осторожная оценка.
4. Провайдер и хранение — по требованиям заказчика (152-ФЗ).

## Этап C. Игровой слой — «нотка игры» (2–3 недели)
Игровой цикл: **дело → решение → разбор → награда → следующее дело**. Награды даются только за качество решений (данные `Evidence`), а не за клики. Ложные тревоги тоже стоят очков: подозревать всех — не победа.

1. **Роль и сюжет.** Вы — новичок вымышленного «Отдела цифровой безопасности». Наставник-персонаж выдаёт дела, звания растут: Стажёр → Оперативник → Детектив → Старший детектив → Начальник отдела.
2. **Семейный кошелёк.** Виртуальные сбережения семьи, например 150 000 ₽, видны всегда. Ошибка списывает деньги. Быстрые правильные действия после ошибки (звонок в банк, блокировка) возвращают часть. Так виден реальный смысл экстренных шагов.
3. **Дела и звёзды.** ★ — не потерял деньги и доступы. ★ — проверил через независимый канал. ★ — закончил разговор вовремя и нашёл все признаки. За 3★ можно перепроходить дело.
4. **Дело дня и серия дней.** Каждую неделю — «операция» по свежей схеме из ленты.
5. **Бестиарий схем.** Карточки схем открываются после победы над ними: признаки, как работает, что делать. Коллекция и прогресс по ней.
6. **«Защити близких».** Персонажи (бабушка, младший брат, коллега) пишут: «мне звонят из банка, что делать?». Вы советуете в реальном времени, а персонаж может не послушаться, если совет неубедительный.
7. **Босс-уровни.** Многоходовые схемы: «Госуслуги» → «ФСБ» → «ЦБ» → «безопасный счёт», с разными голосами на каждом звене.
8. **Карта региона.** Районы «заражены» схемами и очищаются прохождением дел. Для пилота — Пермский край.
9. **Сочность.** Анимации наград, звук, вибрация звонка, итоговый экран дела.
   **Без казино-механик:** никаких лутбоксов, искусственного дефицита и таймеров «вернись, иначе потеряешь».
10. **Метрики игры**: доля дел на 3★, возвраты на 1-й и 7-й день, и главное — рост результата итоговой диагностики.

**Промпт:**

## Этап D. Аккаунты и эксплуатация
- Подтверждение email и восстановление пароля (нужен почтовый сервис).
- Общее ограничение частоты запросов (тогда и появится Redis).
- Кабинет организации в интерфейсе: приглашения, сводка, сравнение диагностик до и после.
- Семья: связь по коду-приглашению, результаты видны только с согласия.
- Распознавание речи на своём сервере (Whisper или Vosk); озвучка — моделями с коммерческой лицензией (см. `docs/THIRD_PARTY.md`).
- Хостинг и база в российском облаке.

## Этап E. Продукт для организаций
- Реальный кабинет организации: сотрудники, отделы, отчёты.
- Учебные фишинг-рассылки — только с юридическим согласованием и согласием сотрудников.
- Telegram-бот: дело дня, проверка подозрительных сообщений.
- Интеграции: вебхуки, LMS (SCORM или xAPI).
- Лента схем с модерацией: черновик → проверка → публикация, у каждой схемы источник и дата.

## Как работать с Claude Code
- Одна задача — одна ветка. Сначала план, потом код.
- В конце задачи: тесты той части, которую меняли (`pytest`, `npm test`, `npm run e2e`), и скриншоты для визуальной проверки.
- Ключи — только в `.env` (он в `.gitignore`). Никогда не вставляйте ключи в чат.
- Изменили контент прототипа — перезапустите `node prototype/tools/export-content.cjs` и тесты backend.
