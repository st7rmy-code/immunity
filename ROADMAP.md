# Дорожная карта

Сейчас у проекта рабочий скелет: сценарии, оценка навыков, ИИ, голоса. Но фронтенд склеен из файлов в один скрипт, игрового цикла нет, сервер умеет только проксировать ИИ.
Порядок важен: **сначала фундамент** (чтобы не строить игру на склейке), **потом игра, потом бэкенд**. Каждый этап заканчивается зелёным `npm test`.

---

- `git init`, первый коммит, `npm install`, `npx playwright install chromium`, `npm test` — всё зелёное.
- Подключить GitHub (приватный репозиторий).

## Этап 1. Фундамент фронтенда (1–2 недели)
Цель — современная сборка, типы и разделение логики, контента и интерфейса.

1. **Vite + TypeScript + React.** Глобальные функции превращаем в модули.
2. **`src/engine/` — чистая логика без DOM**: `Store`, `Evidence`, `Assess`, `Rec`, `localCheck`/`urlRules`/`mailRules`, `normSchema`, сценарный движок звонков (`scriptTurn`), `vKey`. Unit-тесты на Vitest — модель оценки должна давать те же числа, что сейчас.
3. **`content/` — JSON вместо JS**: схемы, звонки, переписки, тесты A/B, сайты, словарь, источники. Плюс JSON Schema и проверка контента в `npm test`, чтобы сценарист мог править тексты без программиста.
4. **UI переносим экран за экраном**: главная → тренировки → прогресс → наставник → остальное. Текущие Playwright-тесты служат регрессом (селекторы `#id` сохраняем).
5. **Дизайн-система**: токены из `src/01-head.html` → CSS-переменные и компоненты `Button`, `Card`, `Phone`, `Modal`, `Toast`, `SkillBar`.

## Этап 2. Игровой слой — «нотка игры» (2–3 недели)
Игровой цикл: **дело → решение → разбор → награда → следующее дело**. Награды даются только за качество решений (данные `Evidence`), а не за клики. Ложные тревоги тоже стоят очков: подозревать всех — не победа.

1. **Роль и сюжет.** Вы — новичок вымышленного «Отдела цифровой безопасности». Наставник-персонаж выдаёт дела, звания растут: Стажёр → Оперативник → Детектив → Старший детектив → Начальник отдела.
2. **Семейный кошелёк.** Виртуальные сбережения семьи, например 150 000 ₽, видны всегда. Ошибка списывает деньги. Быстрые правильные действия после ошибки (звонок в банк, блокировка) возвращают часть. Так виден реальный смысл экстренных шагов.
3. **Дела и звёзды.** ★ — не потерял деньги и доступы. ★ — проверил через независимый канал. ★ — закончил разговор вовремя и нашёл все признаки. За 3★ можно перепроходить дело.
4. **Дело дня и серия дней.** Каждую неделю — «операция» по свежей схеме из ленты.
5. **Бестиарий схем.** Карточки схем открываются после победы над ними: признаки, как работает, что делать. Коллекция и прогресс по ней.
6. **«Защити близких».** Персонажи (бабушка, младший брат, коллега) пишут: «мне звонят из банка, что делать?». Вы советуете в реальном времени, а персонаж может не послушаться, если совет неубедительный.
7. **Босс-уровни.** Многоходовые схемы: «Госуслуги» → «ФСБ» → «ЦБ» → «безопасный счёт», с разными голосами на каждом звене.
8. **Карта региона.** Районы «заражены» схемами и очищаются прохождением дел. Для пилота — Пермский край.
9. **Сочность.** Анимации наград, звук, вибрация звонка, итоговый экран дела.
   **Без казино-механик:** никаких лутбоксов, искусственного дефицита и таймеров «вернись, иначе потеряешь».
10. **Метрики игры**: доля дел на 3★, возвраты на 1-й и 7-й день, и главное — рост результата итоговой диагностики.

**Промпт:**

Сначала покажи схему данных и макет экранов текстом, потом реализуй «Кошелёк» и «Звёзды за дело» как первый вертикальный срез с тестами.

## Этап 3. Бэкенд MVP (2–3 недели)
`server/index.mjs` уже умеет `/api/chat` (Anthropic или любой OpenAI-совместимый провайдер), ограничивает частоту и проверяет вход. Дальше:

1. **Стек**: Node (Fastify или Hono) + PostgreSQL + Drizzle. Позже Redis для таблиц лидеров.
2. **Профили**: анонимный профиль на устройстве, по желанию — вход по e-mail. Для школ — код класса, без персональных данных детей.
3. **API**: `/api/progress` (синхронизация, версия схемы хранилища), `/api/classes`, `/api/leaderboard`, `/api/content` (лента схем).
4. **Кабинет учителя или куратора**: агрегаты по классу, сравнение диагностик до и после.
5. **Семья**: связь по коду-приглашению, результаты видны только с согласия.
6. **Речь на своём сервере**: распознавание (Whisper или Vosk), чтобы голос не уходил к Google и Microsoft. Синтез: заранее озвученные реплики + серверный синтез для реплик ИИ.
7. **Прод в РФ (152-ФЗ)**: хостинг и база в российском облаке. ИИ- и речевой провайдер — по требованиям заказчика (адаптер уже есть).

**Промпт:**
> Этап 3 из ROADMAP.md. Спроектируй схему БД и API для профилей, синхронизации прогресса и классов. Учти: дети без персональных данных, семья только с согласия, хранение в РФ. Покажи схему и эндпоинты, затем реализуй `/api/progress` с миграциями и тестами.

## Этап 4. Продукт для организаций
- Реальный кабинет организации: сотрудники, отделы, отчёты.
- Учебные фишинг-рассылки — только с юридическим согласованием и согласием сотрудников.
- Telegram-бот: дело дня, проверка подозрительных сообщений.
- Интеграции: вебхуки, LMS (SCORM или xAPI).
- Лента схем с модерацией: черновик → проверка → публикация, у каждой схемы источник и дата.

## Как работать с Claude Code
- Одна задача — одна ветка. Сначала просите план, потом код.
- В конце каждой задачи: «прогони `npm test` и покажи скриншоты из `tests/out/`».
- Ключи — только в `.env` (он в `.gitignore`). Никогда не вставляйте ключи в чат.
- Если меняете тексты реплик собеседников, перезапустите `npm run voices`.
